# SIGNAL//BREACH — аудит готовности к Android / RuStore v1

**Дата:** 2026-10-31. **Проверенная основа:** `main` после PR #2 (`eeb3177`).  
**Охват:** код React/TypeScript, движок сапёра, мобильные жесты, настройки и прогресс, аудио, шрифты и ассеты, Vite/CI, архитектура UI, план RuStore.  
**Ограничение:** статический аудит кода + тесты на GitHub Actions. Реальный Android WebView, APK, устройства, поведение ОС и визуальные брейкпоинты **пока не проверены**.

## Результат
**Web-игра пригодна как база Android-приложения. Первый тестовый APK можно планировать после создания изолированного Android-проекта**, но **не считать его готовым к RuStore** до решения задач ниже. Переходить к масштабному рефакторингу ради «красивой архитектуры» сейчас не нужно.

## Приоритет A — до первого полноценного Android-прототипа

| Требование | Что обнаружено | Что сделать | Критерий |
|---|---|---|---|
| Android shell / ассеты | Нет `capacitor.config.*`, `android/`, `@capacitor/core/android/app`; в `vite.config.ts` зафиксирован `base: '/signal-breach/'` для GitHub Pages | В **отдельной ветке** добавить Capacitor и Android-проект, `webDir: 'dist'`, отдельный build с относительным `base: './'`; не ломать Pages | Debug APK запускается полностью офлайн, CSS/JS не запрашиваются по `/signal-breach/` |
| Шрифт / отсутствие сети | `index.html` загружает Unbounded (также Tektur/Russo) через Google Fonts. Без сети фирменный шрифт может подмениться fallback | Взять лицензионный Unbounded в WOFF2, сохранить лицензию, локально подключить только нужные начертания; диагностические шрифты оставить только в веб-режиме | Airplane mode: загрузка, меню, кампания, игровая типографика неизменны |
| Безопасный выход / Back | В React нет навигационной обработки системной Android Back; кнопки Домой/Рестарт немедленно сбрасывают текущую сессию | В Android shell добавить `@capacitor/app` для Back и жизненного цикла. В игре предложить подтверждение или продолжение сессии. Вне игры Back ведёт на логичный предыдущий экран | Аппаратная и жестовая Back не теряют партию без решения игрока |
| Идентичность сборки | Нет стабильного package ID, `versionCode`, icon/adaptive icon, splash | Зафиксировать Android applicationId перед первой публикацией, метаданные v1, иконку и splash, отдельно debug/release config | Воспроизводимая сборка и однозначный пакет без сторонних разрешений |

## Приоритет B — обязательно до RuStore / основного QA

| Проблема | Доказательство | Решение и проверка |
|---|---|---|
| Партия теряется при завершении процесса | `App.tsx`: `session` только в `useState`; `GameScreen.tsx`: `board`, `phase`, `elapsed`, `interactionMode` только React state. `src/stores/progress.ts` сохраняет лишь результаты кампании | Ввести версионированный snapshot текущей сессии: board + generated/mines/revealed/quarantined + phase + elapsed + режим + версия схемы. Сохранять на игровые изменения, перед уходом в фон. Восстанавливать на запуске с выбором «Продолжить / Новая игра». Не сохранять одноразовые `pointer`-жесты |
| Таймер продолжает считать, когда приложение свернуто | `startedAt.current = performance.now()`; на каждом тике `elapsed = floor((performance.now()-startedAt)/1000)` | Разделить накопленное игровое время и момент последнего старта; при `App.pause/appStateChange` (и `visibilitychange` веб) останавливать время и Web Audio, при resume возобновлять без прибавления фонового времени; обеспечить одно событие в обоих каналах |
| Аудио не синхронизировано с жизненным циклом | `audioEngine.ts` управляет одним AudioContext и interval, но не реагирует на фон/возвращение, ошибки `resume` не обрабатываются | Сделать `suspendForBackground` / `resumeIfEnabled`, остановку пульса, защиту от необработанного отказа AudioContext. Не менять установленное игроком on/off при системной паузе |
| Сохранение настроек не защищено | `settings.ts`: `localStorage.getItem/setItem` без try/catch; `progress.ts`: сохранение без обработки ошибки | Добавить безопасный persistence-адаптер и валидацию JSON/version, обработать недоступное хранилище без падения UI. Сохранить язык, звук и выбранный режим управления |
| Тач-жесты и крупные карты пока протестированы только логически | `GameScreen.tsx`: таймер долгого нажатия 430 мс, отмена сдвига 12 px, `pointercancel`, click suppression; размеры карт до 16×30 | E2E на Android: короткий тап, удержание-отпускание, движение после удержания, скролл, мультитач, contextmenu, горизонтальный/вертикальный pan, пересечение системных жестов. Проверка именно на экране устройства |
| Сложность пользовательского тестирования | Нет механизма принудительно разлочить миссии в штатном релизном UI | Только для dev/test — сценарий прогресса с готовыми/выполненными/закрытыми миссиями; отключить для release, не менять игровой баланс |
| Защита от регрессий движка | До аудита `npm run build` запускал проверки строк JSX/CSS, но не поведенческие тесты математики сапёра | Добавить `node:test` для генерации безопасного старта, flood-fill, карантина, chord/взрыва и завершения — выполнено в `prep/android-readiness` |
| Неверная координата при поражении от chord | `GameScreen.finishLoss` получал координаты нажатой безопасной цифры, а не мины, взорвавшейся в `chord` | Исправить через `findExplodedCell(nextBoard)`; лосс-текст и красный прицел должны ссылаться на **настоящую** мину — выполнено в `prep/android-readiness` |

## Архитектура: что выносить в компоненты

| Последовательность | Извлечение | Зачем |
|---|---|---|
| 0 — готово в подготовительной ветке | `AudioToggle.tsx` | Одна доступная кнопка звука для меню и игры, без расхождения иконок / `aria-pressed` |
| 1 — перед интеграцией Android жизненного цикла | `useGameSession` (state, actions, session snapshot) | Одна точка для сохранения/возобновления партии, очистки партии и паузы, без `localStorage` в JSX |
| 2 — после защиты игровыми тестами | `GameBoard` + `GameCell`; отдельно `useCellInput` | Изолировать матрицу кнопок от HUD и сложных touch/pointer событий; сохранить события на `pointerup` |
| 3 — небольшие безрисковые UI-части | `GameHUD`, `GameTopBar`, `ResultOverlay`, `HelpDialog` | Отдельная ответственность, меньше JSX в `GameScreen.tsx`, независимое оформление |
| 4 — по необходимости | `BootScreen`, `CampaignScreen`, `FreeRunScreen`, `BriefingDialog` | Разделить `App.tsx` без глобального роутера, когда экраны действительно будут меняться |

**Важно:** `GameScreen.tsx` содержит не столько «слишком много строк», сколько **сцепление состояния, таймера, ввода и рендера**. Нельзя просто механически нарезать JSX на файлы: это не сделает обновление 480 клеток при изменении таймера дешевле. После появления E2E/профайлинга имеет смысл мемоизировать `GameBoard` при стабильных callback и пропсах.

## UI и ресурсы
- `global.css` ~20 KB фактически минифицированного CSS, `parity.css` содержит слои переопределений. Переносить стили постепенно по модулям, не перестраивая всю тему перед APK.
- Проверить на реальном WebView: 320, 360, 390 dp и большой экран; RU/EN; клавиатура; safe areas, cutout, системные жесты, landscape/portrait. Не считать desktop responsive-эмуляцию полноценной заменой.
- `panHints.ts` использует глобальный `MutationObserver` документа. Если возникнут просадки на слабом Android, привязать observer к board-shell или заменить явным `ResizeObserver`/событиями scroll, но без измерений менять не обязательно.
- `GameScreen` обновляет `elapsed` каждые 250 мс; при каждом таком изменении пересоздаются элементы клеток. Проверить производительность и расход батареи на 16×30, оптимизировать только при подтверждённом профиле.
- Добавить точные `aria-label` к кнопкам закрытия, поправить состояние фокуса и подсказки для screen reader, но до native release это вторичный риск.

## Проверки релиза

**Web:** `npm run build` (TypeScript, Vite, терминология, карточки, звук, engine tests).  
**Android:** `webDir=dist`, отдельный относительный Vite base, `npx cap sync android`, debug APK, offlined launch, Android Back, остановка/возврат, убийство процесса, сохранения, аудио, большие карты.  
**RuStore:** подписанный APK или AAB, уникальный package name; после первой публикации сохранение package + сертификата и увеличение versionCode. Пароли и keystore не хранить в Git.  
Источник Capacitor: https://capacitorjs.com/docs/getting-started ; требования: https://capacitorjs.com/docs/getting-started/environment-setup.  
Источник RuStore: https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication.
