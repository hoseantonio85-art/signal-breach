# UI-компоненты и верстка — SIGNAL//BREACH

## Принцип
Данные и игровая логика не должны определять координату подвала карточки через количество строк в заголовке. Разметка переиспользуемого элемента и его раскладка должны жить рядом и иметь предсказуемый контракт.

## Реализовано в тестовой ветке (до merge)
- `src/components/MissionCard.tsx` — отдельный React-компонент со строго типизированными props: `mission`, `progress`, `t` (словарь), `onSelect`. Сам выбирает состояние `locked / ready / completed` из прогресса. В `App.tsx` теперь только `missions.map(... <MissionCard ... />)`.
- `src/components/MissionCard.css` — весь CSS конкретной карточки в одном месте: верхняя строка, заголовок, **единый нижний блок**, состояния, адаптивность. Раскладка — flex-column, футер `margin-top:auto`, место под метрики зарезервировано на две строки, чтобы статус и сведения оставались на постоянных уровнях.
- `src/styles/card-layout.css` — общие правила фиксации подвалов у двух других видов карточек: выбор Campaign/Free Run на главном экране и выбор плотности во Free Run.
- Стили подключаются после `global.css` и `parity.css` в `src/main.tsx` с явным приоритетом. Дублирующие стили карточки операций из `parity.css` удалены.
- `scripts/check-card-layout.mjs` — статическая проверка структуры разметки и критических CSS-инвариантов; встроена в `npm run build`. Отдельный `check-ui-terminology.mjs` теперь ищет словарную подпись метрики внутри вынесенного компонента.

## UI-контракт карточки миссии
1. **Header**: единая строка **20 px**, жёстко закреплённая сверху. `OP 01` всегда исходного голубоватого `--cyan`, независимо от состояния. Галочка `CircleCheck` только у завершённой и тоже голубоватая.
2. **Title**: `Unbounded`, по словам, не разрывать `PROTOCOL` или `SIGNATURE`. 1–2 строки.
3. **Footer**: сведения `8×8 / 8 BUGS`, статус `READY / COMPLETED / LOCKED`, ранг завершённой операции. Обе строки футера закреплены внизу и не смещаются при переносе заголовка.
4. В одном ряду карточки растягиваются до одинаковой высоты. Изменение статуса не меняет структуру раскладки. `disabled` для закрытых миссий сохраняется.

## Что показал аудит
- Ранее `App.tsx` совмещал маршрутизацию, состояние приложения и полный JSX карточек. Первый самостоятельный компонент выделен. Остальные части экрана пока не стоит разбивать без необходимости.
- `global.css` содержит большую часть исходных стилей в минифицированных строках; `parity.css` копил поздние переопределения. Это риск конфликтов и повторного появления «магических отступов». **Новые карточки и составные элементы нужно оформлять в собственных файлах**, а старые правила постепенно переносить по мере работы, без одномоментного переписывания всей игры.
- У карточек главного меню и Free Run был аналогичный зависимый от содержимого порядок по вертикали. Для них добавлены стабильные flex-правила.
- `GameScreen.tsx` по-прежнему объединяет доску, HUD и оверлеи. Разделять его стоит отдельной задачей с регрессионными проверками жестов и игрового процесса, не в рамках исправления карточек.

## Проверки перед merge
- Типовой desktop, планшет и телефоны **320, 360, 390, 760, 800, 930 px**; RU и EN.
- Во всех рядах сравнить координаты **начала метрик и строки статуса** у однострочных и двухстрочных названий.
- Проверить `CHOIR SIGNATURE`, `WAKE PROTOCOL`, статусы `READY / COMPLETED / LOCKED`, маленький ранг (`S`) и длинные русские надписи.
- Проверить выбор миссии, недоступные миссии, сохранение прогресса, возврат назад.
- Статическая проверка и TypeScript/Vite сборка — обязательны, **но не заменяют визуальный прогон в браузере**.
