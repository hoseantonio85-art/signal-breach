# SIGNAL//BREACH — аудит логической решаемости (только QA)

Скрипт `scripts/analyze-board-solvability.mjs` использует **настоящий** `createBoard/generateBoard/reveal/toggleQuarantine` проекта и псевдослучайный генератор с фиксированными seed **только для тестирования**. Production-генератор, количество мин, UX, скорость и сложность игры НЕ меняются.

Методика: 100 одинаково воспроизводимых полей для каждого OP 06–10 при первом ходе из центра и из угла (всего 1000). Решатель использует только видимые цифры и отмеченные флаги: базовое правило «все / ни одной»; вычитание уравнений вложенных соседств; общее число оставшихся мин. Реальные минные координаты **никогда не используются для выбора хода**, только для автоматического контроля честности дедукций.

**Критически важно:** `stalled` означает «решатель с ограниченным набором логических правил не смог продолжить», а **не** математическое доказательство, что игрок *обязан* угадывать. Существуют более сильные методы: общая система ограничений, перебор согласованных комбинаций / компоненты границы, связи между раздельными группами через общий бюджет мин. Статистику не трактовать как долю «нечестных» карт.

Порядок: сначала оценить базовые результаты, затем при необходимости написать полноценный CSP решатель и лишь после этого решать менять ли `generateBoard`, защищать ли кампанию от 50/50 или добавлять подсказки/сканер.

Результат: CI Actions `Gameplay fairness QA (test only)`, `qa-reports/fairness-op06-10.json` в artifact. Пример seed записан в JSON для повторения конкретной доски. Отдельная ветка `qa/op07-10-solvability`. Никакого merge в игровые/релизные ветки.

## Результаты 2026-11-01

**Первый прогон:** [GitHub Actions 41338789832](https://github.com/hoseantonio85-art/signal-breach/actions/runs/41338789832), 100 seed × 5 OP (06–10) × 2 первых хода = 1000 карт. Решатель по локальным правилам+subset+глобальному числу мин полностью решил 13% OP 06 и 1% OP 07 из центра, 0% OP 08, 1% OP 09, 0% OP 10. **Этот показатель не есть доля гарантированно требующих угадывания карт**, потому что алгоритм неполный.

**Второй прогон:** [GitHub Actions 41339238510](https://github.com/hoseantonio85-art/signal-breach/actions/runs/41339238510), ещё 30 seed × 5 OP × 2 позиции = 300 карт. Добавлен точный CSP-перебор разрешённых состояний границы поля, включая общее число мин. Чтобы не блокировать Android, вычисление ограничено 23 переменными на связный компонент и 250 000 поисковых узлов. Если лимит достигнут, результат — **inconclusive**, не «требует угадывания».

| OP | Центр: решено / доказано угадывание / неопределённо | Угол: решено / доказано угадывание / неопределённо |
|---|---|---|
| 06 | 6 / 15 / 9 | 4 / 25 / 1 |
| 07 | 2 / 22 / 6 | 3 / 26 / 1 |
| 08 | 0 / 16 / 14 | 1 / 26 / 3 |
| 09 | 1 / 16 / 13 | 0 / 28 / 2 |
| 10 | 0 / 16 / 14 | 0 / 29 / 1 |

Здесь «доказано угадывание» означает **конкретное состояние игрового поля после всех однозначно безопасных дедукций, в котором ни одну закрытую клетку нельзя гарантированно безопасно раскрыть по видимым цифрам и общему числу мин**. Решатель не знает настоящих координат мин при выборе хода. Он использует `cell.mine` только после хода как тестовый инвариант, чтобы проверить корректность своих дедукций.

Эти числа **нельзя выдавать за долю всех возможных полей** — выборка небольшая и определяется фиксированными seed/первым ходом. Можно утверждать, что нынешняя генерация действительно допускает поля, приводящие к объективной неопределённости, особенно в поздних операциях.
