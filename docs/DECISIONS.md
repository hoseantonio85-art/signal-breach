# Решения — SIGNAL//BREACH

Формат: решение / причина / критерии проверки. Новые решения добавляются датированными секциями.

## 2026-10-31 — веб-версия остаётся источником для релиза
- Источник: `main`, именно из неё деплоится GitHub Pages.
- Не подменять текущую версию сюжетной экспериментальной веткой.
- Android-порт через Capacitor после проверки UX; не переписывать игровую логику на Kotlin.
- Web и Android используют общий игровой движок.

## 2026-10-31 — UX: действие только при отпускании
- Основное нажатие: кнопка/ячейка активируется после успешного отпускания, не на pointerdown.
- Кнопки меню, справки, перезапуска и пр. используют стандартный `click` по отпусканию (с сохранением клавиатурной доступности).
- Длительное касание ячейки (430 мс): при удержании **ничего не менять**; после отпускания внутри ячейки — один флаг и только флаг.
- Касание без удержания: одно раскрытие / действие выбранного режима после отпускания.
- Если палец переместился для панорамирования (>12 px) — отмена pending long press и отсутствие действия.
- `pointercancel` — отмена, никаких изменений доски.
- Контекстное действие мышью правой кнопкой: флаг **на отпускании** правой кнопки; нативное контекстное меню не показывать.
- Длинное удержание не должно создавать второй `click`, действие не повторяется.
- Поведение перетаскивания, нажатия и клавиатуры должно быть предсказуемо, без «преждевременного» отклика.

## 2026-10-31 — иконки из одной библиотеки
- Использовать `lucide-react`: `Volume2` / `VolumeX`, `RotateCcw`, `House`.
- Не заменять ромб логотипа, маркеры мин или визуальные эффекты игры.
- Иконки SVG, лёгкий тонкий контур, размеры под компактные 36px кнопки.
- Для иконок должны оставаться доступные названия кнопок (aria-label).

## 2026-10-31 — хранение
- Файлы решений, план, чек-лист и версионируемые исходники — GitHub.
- Человеческие задачи и напоминания — TickTick.
- Материалы публикации вне кода — Google Drive только когда они появятся; секреты подписи **не хранить в публичном репозитории или общей папке**.

## Открытые вопросы
- Окончательный Android applicationId / название приложения для магазина.
- Полноэкранность и вертикальная ориентация (предполагаем портрет, проверить на устройствах).
- Как переносить браузерный прогресс в приложение (для v1 допустимо без переноса, но об этом нужно предупредить).
- Состав фактически обрабатываемых данных и требования к privacy policy.

## 2026-10-31 — компактные кнопки на главном экране
- На главном экране и остальных экранах оболочки звук показывается **только библиотечной иконкой** `Volume2/VolumeX`, без текста.
- Кнопка языка показывает только `RU` или `EN` и переключает два языка по нажатию, без выпадающего списка или шеврона.
- Обе кнопки имеют одинаковые квадратные размеры 36×36 px, сохраняют `aria-label` / подсказку.
- Правки ведутся в `feature/release-interactions-icons`; публичный предпросмотр — `/signal-breach/preview/`. В `main` добавлять только после проверки.

## 2026-10-31 — Unbounded выбран для заголовков
- Цель: более широкая, современная display-типографика для заголовков Signal Breach, но без замены читаемого интерфейсного текста.
- **Принято:** Unbounded для крупных заголовков и названий карточек. Tektur и Russo One оставлены только для сравнения.
- Тестовый стенд: https://hoseantonio85-art.github.io/signal-breach/preview/font-lab.html
- Полноэкранная примерка в игре: `/signal-breach/preview/?font=unbounded`, `?font=tektur`, `?font=russo`.
- На этапе тестирования шрифты загружаются с Google Fonts; для Android APK нужно будет **упаковать выбранные файлы шрифта локально** и сохранить лицензии.
- Заголовок `SIGNAL//BREACH` на узких экранах требует отдельного кегля / межбуквенного расстояния. Логотип-ромб, мелкие HUD-метрики и основной интерфейсный текст не менять.
- **Принято:** немного разрядить буквы относительно плотного первичного варианта: h1 +0.005em, другие крупные заголовки от -0.005em до +0.005em, карточки — 0. Визуальное название отображать как `SIGNAL // BREACH`, с пробелами по обе стороны `//`; исходное имя проекта/идентификаторы остаются `SIGNAL//BREACH`.
- Unbounded включён по умолчанию в тестовой feature-ветке, ещё не объединён с `main`. На узком экране немного уменьшен кегль главного заголовка ради сохранения композиции.


## 2026-10-31 — заголовки карточек кампании
- С Unbounded сделать названия операций заметнее: десктоп 16px вместо 13px; мобильные ширины 12.5–14.5px вместо прежних 11px.
- Все десять кодовых имён операций состоят из двух слов; допустим перенос между словами, но нельзя делить длинные слова (например, `SIGNATURE`, `PROTOCOL`) и нельзя получать третью строку.
- При ширине 761–930px показывать три колонки вместо пяти для сохранения свободного места. На мобильных остаётся сетка из двух колонок, до 390px горизонтальные отступы карточек 12px.
- Проверить в предпросмотре узкие Android-экраны, особенно карточки `CHOIR SIGNATURE` и `WAKE PROTOCOL`, до слияния PR.
