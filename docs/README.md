## Процесс работы
1. Изменение требований → дополнить соответствующий документ и при необходимости задачу.
2. Разработка в отдельной ветке → PR с описанием и проверками.
3. Проверить браузерную версию и, после появления Android-сборки, APK на устройстве.
4. Только после проверки объединять изменения с `main`.
5. Перед RuStore заморозить версию, собрать релиз, зафиксировать версию и подписать APK.

## Состояние на 2026-10-31
- React + TypeScript + Vite, 10 сюжетных операций, 3 сложности Free Run, RU/EN, звук.
- Прогресс кампании хранится локально; текущая незавершённая партия не восстанавливается.
- Нативной Android-сборки в репозитории пока нет.
- Веб-деплой: `.github/workflows/pages.yml`, запускается push в `main`.
- Первая UX-правка: все действия на release, а не press-down; длительное нажатие только распознаёт намерение, выставляет флаг при отпускании.
- Вторая UX-правка: заменить аудио, перезапуск и переход домой на иконки из библиотеки Lucide.

## Доступ к игре после merge

GitHub Pages теперь собирает две версии одним workflow `.github/workflows/pages.yml`:
- Стабильная `main`: https://hoseantonio85-art.github.io/signal-breach/
- Исторический UX-предпросмотр (продолжает собираться из ветки feature): https://hoseantonio85-art.github.io/signal-breach/preview/

После merge **основная версия игры находится по корневому URL** и содержит все правки PR #2 и PR #3. Preview остаётся вспомогательной страницей; его наличие не является индикатором актуального состояния основного сайта. Сайт `main` собирается из `main` и находится в корне Pages. При успешном завершении `Validate web build` для feature-ветки workflow `Deploy web preview` запускается с контекстом `main` и заново публикует обе версии, не переписывая исходники игры в `main`. Кроме этого, workflow можно запускать вручную из GitHub Actions (`Run workflow` на `main`). В случае ошибки сборки preview не публикуется; см. Actions.
